# Local PII Masker

日本語テキストに含まれる個人情報・機密情報を、ブラウザ内で検出して可逆的にマスキングするWebアプリケーションです。

原文、検出結果、マスク対応表は外部へ送信せず、通常はブラウザメモリ内だけで扱います。ユーザーが明示的に保存した場合だけ、再利用に必要なマスク対応表を暗号化して同一オリジンのOPFSへ保存できます。原文を含む作業セッションは保存しません。マスク済みテキストを外部の生成AIなどへ渡し、マスクを含む文章に保持されたマスクトークンをローカルで対応する復元文字列へ置換する利用を想定しています。

> 本アプリの「復元」は、マスクを含む文章に残っているマスクトークンを対応する復元文字列へ置換する機能を指します。検出時にOCR由来の全角文字、ハイフン、空白、改行等を補正して成立した対象は補正後の文字列へ、それ以外の対象は原文表記へ置換します。AIによって削除・改変された情報を意味的に復元するものではありません。

## MVPの目的

- 日本語テキストから個人情報・機密情報の候補を検出する
- ユーザーが検出結果を確認・修正できるようにする
- 原文とマスク結果を比較し、マスク漏れを確認できるようにする
- マスク済みテキストを外部サービスへ安全に受け渡しやすくする
- 外部サービスなどで処理したマスクを含む文章をブラウザ内で復元する

## 想定利用フロー

1. 原文を入力または貼り付ける
2. 自動検出で、形式候補と日本語NER候補を検出する
3. 有効化された対象を確認・無効化・削除し、必要な対象を手動で追加する
4. 「原文」と「マスク結果」を切り替えて確認する
5. マスク済みテキストをコピーし、外部の生成AIなどへ渡す
6. マスクを含む文章を貼り付ける
7. 文章内のマスクトークンを対応する復元文字列へ置換する

## MVPの主要ルール

- 同一文字列は、原文中の全出現箇所を一括してマスクする
- 出現箇所ごとの個別指定は行わない
- `山田`と`山田太郎`のような包含関係にある文字列を両方登録できる
- 同じ位置で複数の対象が一致する場合は最長一致を優先する
- 原文は編集可能、マスク結果は読み取り専用とする
- マスク結果は原文とマスク対象一覧から都度生成する
- ユーザーが保存を確定していないデータはメモリ内だけに保持し、ページ更新・タブ終了時に破棄する
- 明示保存時は、マスク対象文字列とマスク文字列の対応関係だけを暗号化してOPFSへ保存し、対応表名など一覧用の限定メタデータだけを平文で保持する
- AIモデルなどの公開資材はブラウザキャッシュを利用できる

## MVPの前提環境

- 主対象：PC
- OS：Windows 11、macOS
- 正式対応候補：Google Chrome最新版
- 準対応候補：Microsoft Edge最新版
- ネットワーク：安定したブロードバンド環境を推奨
- 対象言語：日本語
- スマートフォン、タブレットは正式対応外

## 技術方針

| 項目 | 方針 |
| --- | --- |
| フロントエンド | React + TypeScript + Vite |
| 原文エディター | CodeMirror（入力、選択、候補背景色を同一描画面で処理） |
| NER実行基盤 | Transformers.js |
| モデル形式 | ONNX |
| MVP採用NERモデル | `jiting/xlm-roberta-ner-japanese_onnx` |
| 構造化PII検出 | 正規表現・検査ロジック（メール、電話番号、郵便番号、URL、IPアドレス、認証情報、生年月日、日本語住所、人名補助） |
| AI推論 | Web Workerで実行（WASM / q8、320文字・64文字重複の長文分割） |
| 永続保存 | 既定では行わない。明示保存時だけ暗号化してOPFSへ保存 |
| 外部生成AI連携 | API連携せず、コピー＆ペーストで利用する |

## 開発ステータス

Phase 1として可逆マスキング、手動追加、候補管理、マスク結果コピー、セッション消去の基本機能を実装済みです。

Phase 2以降の形式検出として、メールアドレス、電話番号、郵便番号、`http://`・`https://` URL、IPv4・IPv6アドレス、明示ラベル付きのユーザーID・パスワード・生年月日、市区町村と番地表現を含む日本語住所の検出と候補統合を実装済みです。メールアドレスは`@`前後に半角または全角空白が入ったOCR崩れも検出用テキスト上で補正し、位置マッピングによって空白込みの原文表記へ戻して候補化します。自動検出候補は有効なマスク対象として追加され、検出直後からマスク結果へ反映されます。不要な対象は後から個別に無効化でき、再検出でも無効状態を維持します。カテゴリは検出時または手動追加時に決定し、登録後のカテゴリ変更は現時点では行いません。

Phase 3として、MVP採用モデル`jiting/xlm-roberta-ner-japanese_onnx`によるブラウザ内NER検出を追加しています。NERはWeb Workerで実行し、320文字・64文字重複で長文を分割します。検出元`AI検出`、信頼度、有効な初期状態を候補管理に統合し、モデル取得や推論に失敗した場合も形式検出と手動追加を継続できます。NER処理は5分でタイムアウトし、処理中は同じボタンから中止できます。失敗、タイムアウト、中止ではWorkerを破棄し、次の再検出でWorkerとモデル初期化を再生成します。原文変更と全消去でも進行中の処理を中止し、古い検出結果を反映しません。人名補助では姓名間の半角・全角空白に加え、漢字名の途中にOCR由来の空白が1文字分入った表記を原文どおり検出します。さらに、AI検出した一般姓を持つ漢字姓名を根拠に、各文字間へ半角または全角空白が0〜1文字入った原文中の表記も形式候補として補完します。空白を1文字以上含む表記だけを補完し、空白2文字以上、タブ、改行は文字間区切りとして扱いません。Markdown表・CSVの人名列、JSON・キー値行の既知人名フィールドも保守的に検出します。英語氏名は、明示的な人名ラベルまたは構造化フィールドにあるTitle Case・全大文字表記と、NERが`PER`として返した文字列を対象にし、文脈のない英単語2語は形式検出しません。1件以上の検出済みフルネームを根拠に、原文中に独立して出現する2文字以上の一般姓も初期有効の姓単独候補として補完します。姓候補は同一文字列の全箇所をマスクするため、同姓で始まる非人名複合語内も置換対象になります。また、既知フルネームと独立姓を根拠に、Markdownの単一値コードブロックにある同姓別姓名も条件付きで補完します。NERの短い候補は構造検出済みフルネームを優先し、一般姓の住所誤分類や長い複合語内にしか存在しない2文字候補を抑制します。

現在の原文入力上限は30,000文字です。10,000文字の既存実測を基準に、30,000文字でのChrome・Edge、メモリ使用量、境界検出、UI応答性を追加検証します。

選定用100文書と、正解文字列が重複しない最終確認用100文書を用意し、現行`jiting`と`sabaridsnfuji` Q8を比較しました。未見データではアプリ統合後のPrecision 75.0%、Recall 72.0%、F1 73.5%が両モデルで一致し、合計200文書でもF1差は0.5ポイントでした。独自ONNX配布を増やす改善幅ではないため、`jiting`をMVP採用モデルとします。Windows 11のChrome Workerでは、ウォーム状態の10,000文字を約59.6秒で処理し、推論中もUI応答を維持しました。ONNX RuntimeのWASM/MJSはアプリ資産として同一オリジン配信し、実行時CDN依存を除去しています。

NERモデル選定は完了しました。8GB級PC、macOS Chrome、低速回線・初回取得失敗時の確認は後続フェーズへ延期します。

Phase 5の初期ハードニングとして、CSPとセキュリティヘッダー、入力内容のネットワーク・Storage・Console漏えい検査、Chromium・Microsoft Edgeのブラウザ試験、axeによるWCAG 2 A / AA検査、1,000文字・10,000文字のコア性能計測を追加しました。Windows 11上のChromium 149とEdge 150で各3件のブラウザ試験が成功しています。本番配布時は、CSPメタタグに加えて配信ホストで同等のHTTPヘッダー設定が必要です。

Phase 6のOCR対応として、メール・URL・電話番号に含まれる全角ASCII互換文字とハイフン類を検出用テキスト上で補正し、メールの`@`・`.`、URLの限定した構造記号、電話番号の数字・ハイフン間、行末ハイフン周辺にある複数の単一改行を除去して検出します。行末ハイフンは保持します。都道府県・市区町村・町域・番地の境界で折り返された住所も、完全な住所形式になる範囲だけを1件の候補として復元します。`株式会社`等の会社種別接頭辞に続く組織名の最大3行の改行は検出用テキスト上で結合し、NERが見逃した場合も形式検出候補として組織名全体を候補化します。候補直後の`です`・`など`等の文脈語や`営業企画部`等の部署名は候補に含めません。氏名では、限定的な姓名間改行と、`山 田 太 郎`の完全分割表記、`山 田　太郎`のような混在表記を補正し、一覧行等の`鈴木一郎すずきいちろう`は漢字姓名だけを候補化します。候補は改行・空白込みの原文範囲へ戻し、候補カードには適用した補正内容を日本語チップで表示します。電話番号内の郵便番号候補、読み仮名やメール・URL等の構造化候補内にあるNER断片、より長い組織・住所候補に包含されるNER断片を原文位置に基づいて除外します。通常文、空行、Markdown区切り・見出し・コードブロックを誤結合しません。

Phase 7として、PWAインストール情報、Service Workerによる公開資産のみのキャッシュ、オフライン時の形式検出・手動追加への縮退、モデル利用状態の表示、更新時のセッション保護を実装しました。ユーザーが明示保存していない入力、マスク対応表、復元結果は永続化・キャッシュ・送信しません。明示保存による暗号化マスク対応表の要件と実装を追加しています。詳細は[Phase 7 PWA・オフライン実行対応要件](docs/phase7-pwa-requirements.md)と[マスク対応表のローカル保存要件](docs/local-work-history-requirements.md)を参照してください。

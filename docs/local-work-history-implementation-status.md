# マスク対応表の実装確認メモ

確認日：2026-08-13

本書は、[マスク対応表のローカル保存要件](local-work-history-requirements.md)、[画面設計仕様](ui-design.md)と、現在の実装との差異を明示するためのメモである。要件を置き換えるものではなく、未達項目を実装済みと誤認しないために使用する。

## 実装と一致している範囲

- `originalText`、`maskedText`、外部回答、復元結果、画面状態を永続化せず、有効なマスク対応表だけを保存する。
- 対応表本文をAES-GCM、PBKDF2、gzipで暗号化し、EnvelopeヘッダーをAADで認証する。
- 平文インデックスには対応表ID、対応表名、作成・更新日時、暗号化ファイル名、フォーマットバージョン、リビジョンだけを保持する。
- 管理一覧、別ダイアログでのパスフレーズ入力、上書き／新規保存、個別削除、全削除、現在の作業との紐付け解除を実装している。
- 保存時の一時ファイル検証、インデックスのバックアップ、Web Locksまたはリビジョンによる競合検出を実装している。

## 現在の差異・未達項目

### 対応表を開いた後の復元セクション

要件では、対応表を開いた後に復元セクションを閉じることとしている。現在の`loadMaskMapping`は外部回答が入力中の場合の読み込みを拒否し、外部回答・復元結果を復元しないが、`restoreExpanded`を明示的に`false`へ戻していない。復元セクションを開いた状態で対応表を開いた場合、この受入条件は未達である。

### 孤立ファイル・一時ファイルの起動時検出

要件では、インデックスにない暗号化ファイルを孤立ファイルとして保持し、一時ファイルを未完了処理として検出して削除候補にすることとしている。現在のRepositoryはインデックス項目に対応するファイルの欠損を`missing`として表示し、インデックス破損時にバックアップを試行するが、起動時に`mappings`と`temporary`を走査して孤立ファイル・一時ファイルを一覧へ提示する処理は実装していない。

### Repository層のテスト

暗号、スナップショット、Reducer、ダイアログのテストは存在する。一方、OPFS APIを模したRepository結合テストは未整備であり、インデックス破損、バックアップ復旧、書き込み失敗時のロールバック、孤立・一時ファイル検出、Web Locks非対応時の競合を自動検証できていない。

## 取り扱い

上記の未達項目が解消されるまで、要件文書の障害復旧と復元セクション閉鎖に関する受入条件を「実装済み」と扱わない。次の実装作業では、まずReducerの復元セクション状態、次にRepositoryの起動時復旧と結合テストを対象とする。

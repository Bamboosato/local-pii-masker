# ADR-004: ユーザーデータの永続保存境界

## ステータス

採用

## 背景

Local PII Maskerは、原文、検出結果、マスク対応情報を外部へ送信せず、通常はブラウザメモリ内だけで処理してきた。一方、ユーザーが明示的に作業を再開したい場合には、ローカル保存の需要がある。

## 決定

デフォルトではユーザーデータを永続保存しない。ユーザーが明示的に保存操作を行った場合に限り、原文およびマスク編集状態をAES-GCMで暗号化し、同一オリジンのOPFSへ保存する。外部サーバーおよびクラウドへの送信・保存は行わない。

暗号化セッションと一覧用インデックスを分離する。原文、検出値、マスク対応情報などの機密データは暗号化する。一覧表示に必要なタイトル、保存日時、文字数、マスク対象件数などの限定メタデータは平文で保持する。タイトルはユーザー入力であり、個人情報を入力しないよう画面で警告する。

`maskedText`、`externalResponse`、`restoredResponse`、一時的UI状態は保存しない。復元時にマスク結果を再生成し、外部回答と復元結果は空にする。

## 却下した選択肢

- 自動保存：明示操作なしの永続化を避けるため採用しない
- LocalStorage、SessionStorage、IndexedDB、Cookie：機密データの保存先として採用しない
- Service Worker・Cache Storage：公開資産キャッシュとユーザーデータを混在させないため採用しない
- サーバー・クラウド：外部送信を避けるため採用しない
- 暗号化インデックス：一覧表示のたびにパスフレーズが必要になり、MVPの操作性を損なうため採用しない

## 結果

保存機能を利用する場合は、タイトルやサイトデータの消失リスクをユーザーへ説明する必要がある。OPFS非対応環境では保存機能を縮退させるが、既存の一時利用は維持する。保存・削除・インデックス更新には、一時ファイル、バックアップ、リビジョンまたはWeb Locksによる競合制御を用いる。

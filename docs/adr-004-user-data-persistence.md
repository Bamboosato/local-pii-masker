# ADR-004: マスク対応表だけを明示操作でOPFSへ保存する

- 状態：Accepted
- 日付：2026-08-13

## Context

原文や検出値を外部へ送信しないローカル処理を維持しながら、同じマスク対応を別の原文へ再利用したい。原文を含む作業セッションを永続化すると、保存範囲と消去範囲が広がり、利用者が意図しない機密情報を残すリスクが高い。

## Decision

デフォルトではユーザーデータを永続保存しない。ユーザーが明示的に保存操作を行った場合に限り、マスク対象文字列とマスク文字列の対応関係をAES-GCMで暗号化してOPFSへ保存する。外部サーバーおよびクラウドへの送信・保存は行わない。

対応表へ保存するのは、再適用・復元に必要な有効エントリ、復元文字列、種別、検出元、手動フラグ、関連ID、マスク方式、スキーマ・対応表メタデータだけとする。`originalText`、`maskedText`、`externalResponse`、`restoredResponse`、位置、候補の無効状態、UI状態は保存しない。

一覧用`index.json`は平文とし、ランダムID、対応表名、作成・更新日時、暗号化ファイル名、フォーマットバージョン、リビジョンだけを保持する。対応表名は暗号化されないため、個人情報を入力しない注意を表示する。

保存処理は一時ファイル、復号検証、バックアップ、リビジョン競合検出を使用する。Web Locks APIがあれば排他し、なければ楽観的競合検出を行う。OPFS非対応時は対応表機能だけを無効化し、従来のインメモリ処理を維持する。

## Consequences

- 再読み込み後に原文や作業画面を復元する機能は提供しない。
- 保存済み対応表は新しい原文へ再検索して適用するため、出現位置を保存する必要がない。
- 既存の同一人物関連付けが一つのトークンを複数対象へ割り当てる場合、MVPの一対一制約により対応表の保存を拒否する。
- 平文インデックスの対応表名は機密情報になり得るため、入力注意と削除UIを用意する。

## 既定設定と作業差分

既定は `prompt-pii-v1` / `entities-v1`、日本語指示、1,600文字・重複200、区間60秒・全体300秒のまま。`omitResponseConstraintInput`、`constrainEvidence`、`reuseIdenticalChunks`はすべてfalse、固定例は空配列。temperature・topK・topP・samplingModeは指定していない。Web向け安定APIの範囲を維持し、Origin Trialやフラグで生成パラメータを迂回していない。

以下は未完了の実装差分で、全チェック・実UI回帰はまだ済んでいない。

- `adapter.ts`：固定指示、指示言語、固定合成例、カテゴリ別制約、スキーマ自動入力の有無を実APIのまま比較するfactoryを追加。原文引用候補のenum制約と、原文・例外文を含まない任意の失敗診断も追加した。通常UIの引用制約はまだ有効化していない。
- `run.ts` / `chunks.ts`：評価用の小さい窓、整数値の検証、実行内メモリに限る完全一致区間の再利用と推論・再利用件数を追加。通常UIの再利用はまだ無効。成功した応答も各区間位置で検証し直し、終了・失敗時はMapをclearする。後半失敗を部分成功にしない。
- `validation.ts`：重なる根拠引用と対象位置の直積で重複位置を多数列挙していた箇所を、整列区間の線形探索へ変更。同じ対象位置には一つの有効な根拠を保持する。上限を超える大量候補の拒否は維持している。
- `sourceQuotes.ts`：原文の連続部分だけを引用候補にする。短い窓に加えて全区間も必ず残し、長い対象を候補生成時に切り捨てない。JSON形式はtext/category/evidenceのまま。
- `corpus.ts`：`createLongCorpus("development")`と、反復だけで速度を過大評価しない非反復の調整用長文を追加。従来の引数なし呼出しと最終確認用の値は変更していない。
- `experiments/prompt-api/tuning.ts`：調整用文書だけを使う比較器。生応答を保存せず、漏れ・誤マスク・警告・生成文字数・引用長・再利用件数を集計する。失敗時は空の抽出結果で漏れを計上し、完了率と分ける。

### 原因の確度

- **確認済み**：原文に存在する一般語をADDRESS等と誤分類する例がある。完全一致検証だけでは意味分類の誤りを防げない。
- **確認済み**：原文にない根拠引用・対象を含まない引用があり、現在の検証は正しく棄却している。引用候補を原文へ制約する案では警告を減らせたが、生成時間・漏れへの影響がある。
- **確認済み**：同じ対象位置が多数の重複根拠に含まれると、旧位置計算は直積を作り、重複を含めて上限へ到達し得た。線形探索へ修正し回帰テストを追加した。
- **確認済み**：失敗は一種類ではない。保存済みの512文字診断では、生成中67文字で失敗した例は中止・文脈上限・応答サイズ上限のすべてfalse。別の空白付き境界文は6,466文字を生成し、中止signalがtrueになった。
- **未確定**：前者の実API拒否の種類。例外文を出さず、固定の例外名とlanguage/safety/constraint/model/otherだけへ分類する診断を最後に追加したが、実モデルの最新結果は未保存。言語宣言、モデル側の拒否、形式制約などを断定しない。
- **未確定**：反復や空白が多い入力で生成が長引く要因、最適な分割長、非反復30,000文字での性能。空白生成の暴走なども仮説の段階で、成功結果と取り違えない。

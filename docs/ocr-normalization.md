# Phase 6 OCR崩れ対応

## 1. 目的

OCRやPDFテキスト抽出で生じる表記崩れを、原文を変更せずに検出用テキストだけで補正する。検出結果は位置対応マップを使って原文上の連続範囲へ戻し、マスクは原文表記へ適用する。

処理フローは以下とする。

```text
原文
↓
用途別の検出用正規化
↓
形式検出
↓
正規化範囲を原文範囲へ変換
↓
原文表記の候補として統合・マスク
```

## 2. 初期実装

### 2.1 対応ルール

| ルール | 内容 | 適用先 |
| --- | --- | --- |
| `fullwidth_ascii` | `！`～`～`の全角ASCII互換文字を半角化 | メール、URL |
| `hyphen_variants` | `−`、`ー`、`―`、`‐`、`–`、`—`等をASCIIハイフンへ統一 | メール、URL |
| `email_at_spacing` | メールの`@`前後にある半角・全角空白を除去 | メール |
| `email_line_break` | メールの`@`またはドメインの`.`周辺にある単一改行を除去 | メール |
| `url_line_break` | URLの`.`、`/`、`?`、`&`、`=`、`#`周辺にある単一改行を除去 | URL |
| `person_name_line_break` | 限定条件を満たす姓名間の単一改行を除去 | NER |
| `japanese_inter_character_space` | 完全分割表記と一般姓で始まる混在表記の単一空白を除去 | 形式検出、NER |

`fullwidth_ascii`と`hyphen_variants`は構造化PII検出用に限定する。NERへ無条件適用すると、カタカナの長音`ー`などを壊すため、NER入力全体へは適用しない。

### 2.2 検出例

```text
ｔａｒｏ．ｙａｍａｄａ＠ｅｘａｍｐｌｅ．ｃｏ．ｊｐ
taro.yamada@
example.co.jp
https://dev.example.
jp/login
山田
太郎
山 田 太 郎
山 田　太郎
山　田太　郎
佐　藤　健　一
```

候補の`originalText`は、全角記号や改行を含む原文表記を保持する。同じ原文表記が複数回ある場合は、既存要件どおりすべて同じトークンでマスクする。

## 3. 誤結合防止

- 通常文の改行は削除しない。
- URL改行は構造記号の隣に限定する。
- Markdownの`---`をURLのハイフン継続として扱わない。
- Markdown見出し、表、コードフェンスを原文上で変更しない。
- 姓名間改行は前行末・次行先頭が各1～3文字の漢字列で、前側が行頭または区切り文字に接する場合だけ除去する。
- 姓名間に句読点・空行がある場合や、Markdown見出し・コードブロック内では除去しない。
- 日本語文字間スペースは、3～7文字の漢字・カタカナが各文字間の単一空白で完全に分割された場合と、一般姓で始まり空白が2か所以上ある混在表記だけ除去する。一般姓で始まる漢字姓名は、NERが個別の出現位置を返さない場合に備えて形式候補としても直接登録する。
- 単語間空白1個、連続空白、タブ、改行、前後が漢字・カタカナへ連結する部分範囲は除去しない。
- 同じ姓名へ正規化される複数の原文表記は、NER候補を位置ごとに保持して個別に原文範囲へ戻す。
- 正規化後テキストを原文やマスク結果として保存しない。

URLのハイフン位置での改行結合は、Markdown区切りとの誤認を避けるため初期実装の対象外とする。

## 4. テスト観点

- 機能観点：全角メール・URL、区切り位置で改行したメール・URL、姓名間改行、各文字間空白を候補化できること
- 非機能観点：原文を変更せず、既存の10,000文字上限と性能予算を維持すること
- データ観点：半角・全角混在、LF・CRLF、複数区切り、同一文字列の複数出現を確認すること
- UI観点：候補カード、原文ハイライト、マスク結果が同じ原文範囲を示すこと
- 正常系：正規化後の有効なメール・URLを原文表記へ戻せること
- 異常系：通常文の改行、URL直後の次行、Markdown区切りを結合しないこと
- 境界値：候補先頭・末尾、サロゲートペア前後、CRLFを含む範囲を確認すること
- 状態遷移：再検出でも候補を重複作成せず、有効・無効状態を維持すること

## 5. 継続課題

優先順は以下とする。

1. 住所の行折り返し
2. メール・URLの複数行折り返しとハイフン継続
3. 正規化ルールの候補カード表示

住所折り返しは都道府県・市区町村・番地表現の連続性を確認し、一般文の改行を誤結合しない条件が必要となる。

以下は引き続き対象外とする。

- OCRエンジン、画像、PDFの読み込み
- `O/0`、`I/1`などOCR誤認識文字の自動訂正
- 縦書き1文字改行の完全対応
- LLMによる補正

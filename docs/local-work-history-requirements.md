# ローカル作業履歴 追加要件

## 1. 位置づけ

本書は、ユーザーの明示操作によるローカル作業履歴の保存・復元要件を定義する。保存はサーバーやクラウドを使用せず、同一オリジンのOPFSで完結する。

デフォルトではユーザーデータを永続保存しない。ユーザーが明示的に保存操作を行った場合に限り、原文およびマスク編集状態を暗号化してOPFSへ保存する。外部サーバーおよびクラウドへの送信・保存は行わない。

本機能は既存の一時利用を置き換えない。OPFS非対応、容量不足、アクセス拒否などの場合も、保存機能だけを利用不可または失敗とし、入力・検出・マスキング・復元の一時利用は継続できること。

## 2. 保存境界

### 2.1 保存するデータ

暗号化されたセッションファイルには、次のデータだけを保存する。

- `schemaVersion`
- セッションID
- 作成日時・更新日時
- `originalText`
- 復元に必要な永続化対象の`MaskEntry`
- 候補の有効・無効状態
- 手動追加・編集内容
- マスク種別、検出元、トークン対応
- `occurrenceMaskingMode`

永続化する`MaskEntry`は、現行ドメインモデルで復元に必要な項目を明示的に抽出する。`occurrenceCount`など原文と設定から再計算できる値は正本とせず、読み込み時に検証・再計算する。

### 2.2 保存しないデータ

- `maskedText`
- `externalResponse`
- `restoredResponse`
- 通知、ダイアログ、選択タブ、展開状態などの一時的UI状態
- 暗号鍵、パスフレーズ

復元時は`originalText`、`MaskEntry`、マスク設定だけを復元する。`maskedText`は既存ロジックで再生成し、`externalResponse`と`restoredResponse`は空にする。復元セクションは閉じた状態とする。

外部回答の変更は未保存変更の判定対象に含めない。

## 3. 履歴インデックス

一覧表示の利便性のため、`index.json`は平文で保持する。平文で保持できる項目は次に限定する。

- ランダムなセッションID
- ユーザー指定タイトル
- 作成日時・更新日時
- 原文の文字数
- マスク対象件数
- 暗号化ファイル名
- 暗号化フォーマットのバージョン
- 競合検出用リビジョン

`index.json`には、原文、原文の抜粋、検出値、トークン対応、マスク内容を含めない。タイトル、ファイル名、ディレクトリ名、ログにも原文や検出値を含めない。

画面および文書では「保存データはすべて暗号化」と表現しない。次の説明に統一する。

> 原文、検出値、マスク対応情報などの機密データは暗号化されます。履歴一覧に表示するタイトル、保存日時、文字数、マスク対象件数は暗号化されません。

タイトル入力画面には次の注意を表示する。

> タイトルは暗号化されません。氏名、住所などの個人情報を入力しないでください。

## 4. 暗号仕様

- 暗号化：AES-GCM
- 鍵長：256bit
- GCMタグ長：128bit
- 鍵導出：PBKDF2
- ハッシュ：SHA-256
- Salt：保存処理ごとに暗号学的乱数で16byte生成
- IV：暗号化ごとに暗号学的乱数で12byte生成
- パスフレーズ：12文字以上
- パスフレーズのUnicode正規化：NFKC
- 圧縮：gzip
- 処理順：JSON → UTF-8 → gzip → AES-GCM
- 暗号鍵およびパスフレーズ：永続保存しない
- 上書き保存：パスフレーズを再入力する
- 鍵の保持期間：保存または復元処理中だけとする

PBKDF2の反復回数は、対象端末で鍵導出時間が概ね250〜500msになる値を性能測定して決定する。決定値は暗号化ヘッダーへ保存し、最低許容反復回数を定数として定義する。最低許容値未満のファイルは復元を拒否するか、明示的な警告を表示する。

保存時と復元時の双方で、入力されたパスフレーズへ同一のNFKC正規化を適用する。パスフレーズ不一致とデータ破損は断定的に区別せず、復号済みデータ、パスフレーズ、原文をログへ出力しない。

## 5. 暗号化Envelope

暗号化ファイルは、平文ヘッダーと暗号本文を持つバージョン管理可能なEnvelope形式とする。

```ts
type EncryptedSessionEnvelope = {
  header: {
    format: "local-pii-masker-session";
    formatVersion: number;
    kdf: "PBKDF2";
    hash: "SHA-256";
    iterations: number;
    salt: string;
    cipher: "AES-GCM";
    keyLength: 256;
    iv: string;
    tagLength: 128;
    compression: "gzip";
  };
  ciphertext: string;
};
```

`format`、`formatVersion`、KDF・暗号・圧縮パラメータは、フィールド順と値の表現が固定された決定的形式でシリアライズする。そのバイト列をAES-GCMのAADに指定し、ヘッダー改ざんも認証失敗として検出する。Envelope形式とシリアライズ規則は、実装前にテストベクトルで固定する。

## 6. OPFS構成

```text
local-pii-masker/
├─ index.json
├─ index.backup.json
├─ sessions/
│  └─ {session-id}.session.enc
└─ temporary/
   ├─ {session-id}.tmp
   └─ index.tmp
```

`navigator.storage.getDirectory()`の使用は専用Repository層に限定する。ファイル名にはランダムなセッションIDだけを使用し、パス区切りやユーザー入力を受け付けない。

## 7. 保存の原子性と障害復旧

保存時は一時ファイルへ書き込み、読み戻し可能性と形式を検証してから正式ファイルへ反映する。上書き保存に失敗した場合は、既存の正常なセッションファイルとインデックスを維持する。OPFSに完全な原子的置換が保証されるとは仮定せず、利用可能なAPIの保証範囲を確認して実装する。

起動時の復旧方針は次のとおりとする。

- `index.json`破損：`index.backup.json`からの復旧を試みる
- インデックスのみ存在：一覧に保存データ欠損として表示し、削除可能にする
- セッションファイルのみ存在：孤立ファイルとして保持し、自動削除しない
- 一時ファイルのみ存在：未完了処理として検出し、安全性を確認して削除候補とする
- セッションファイル破損：一覧情報を残し、「データを開けません」と表示する
- インデックス更新失敗：新規セッションファイルを孤立状態で残さないよう、可能な範囲でロールバックする

暗号化ファイルだけからタイトルを復元できないため、インデックスの完全な自動再構築は保証しない。

## 8. 未保存変更

保存または復元が完了した時点の永続化対象データから、安定した順序でフィンガープリントを生成する。現在の状態から同じ対象を生成し、比較して未保存変更を判定する。

判定対象は、原文、永続化対象の`MaskEntry`、候補の有効・無効状態、手動追加・編集内容、トークン対応、マスク方式とする。`maskedText`、`externalResponse`、`restoredResponse`、一時的UI状態、表示用の日時は判定対象外とする。

保存失敗時は保存済みフィンガープリントを更新しない。復元失敗時は現在の作業状態とフィンガープリントを変更しない。

## 9. 複数タブと競合

同じ保存データに対する複数タブからの同時更新は正式対応しない。ただし、データ破損防止のため次を行う。

- Web Locks APIが利用可能な場合、保存・削除・インデックス更新を排他制御する
- 利用できない場合、リビジョン番号または更新日時で楽観的競合検出を行う
- 読み込み時と保存直前でリビジョンが異なる場合は上書きしない
- 競合時は再読み込みまたは名前を付けて保存するよう案内する
- 閲覧・復元は複数タブで許可する

## 10. UI操作

ヘッダーの表示は「ローカル処理・外部送信なし」とする。メニューには次を配置する。

- 現在の作業を保存
- 保存済みの作業を開く
- 保存済み作業を開いている場合の上書き保存
- 名前を付けて保存
- 現在の作業を消去
- ローカル保存設定

保存・復元処理中は重複操作を無効化し、進行中であることを通知する。OPFS非対応時は保存操作を無効化し、理由を表示する。保存機能が利用できなくても、既存の一時利用機能は使用できること。

「現在の作業を消去」は現在のインメモリ作業だけを初期化し、OPFSの保存済み作業は削除しない。「保存済みの作業を全削除」はアプリが管理するOPFS内の保存データだけを削除し、現在画面上の作業は自動的に消去しない。

## 11. テスト要件

### 単体

- 安定した永続化対象フィンガープリント
- JSON、gzip、Envelope、AADの決定性
- AES-GCM、PBKDF2、NFKC、テストベクトル
- Envelopeとセッションデータのバリデーション
- スキーマ移行と未対応バージョン拒否
- インデックスの追加、更新、削除、バックアップ復旧

### 結合

- 新規保存から復元まで
- 上書き保存とリビジョン競合
- マスク候補の有効・無効、手動追加、関連付けの復元
- 復元後のマスク結果再生成
- 保存・復元・削除失敗時の現在状態と既存データ維持
- インデックスとセッションファイルの不整合処理

### E2E・セキュリティ

- メニュー、ダイアログ、キーボード、フォーカス復帰
- 再読み込み・ブラウザ再起動後の復元
- OPFS非対応時のフォールバック
- OPFS内に原文、検出値、トークン対応、マスク内容の平文がないこと
- `index.json`に許可外のデータがないこと
- LocalStorage、SessionStorage、IndexedDB、Cookie、Cache Storage、Service Worker、ネットワーク、Consoleへのユーザーデータ非混入
- 誤パスフレーズ、改ざん、破損、未対応スキーマで復号済みデータが残らないこと
- 30,000文字付近の保存・復元でUIが応答不能にならないこと

## 12. 受入条件

- 明示的に保存しない限り、原文とマスク情報は永続保存されない
- 保存した作業を同一オリジンのブラウザ再起動後に復元できる
- 原文、候補状態、手動編集、トークン対応、マスク方式を再現できる
- 復元後に`maskedText`が既存ロジックで正しく再生成される
- `externalResponse`と`restoredResponse`は復元されず空になる
- OPFS内に機密データの平文が存在しない
- 履歴インデックスには許可された平文メタデータだけが存在する
- 誤パスフレーズや改ざんデータでは現在作業を変更せずに失敗する
- 暗号鍵とパスフレーズが永続保存されない
- OPFS非対応でも従来の一時利用が可能である
- 外部サーバー、クラウド、公開資産キャッシュへ機密データを送信・保存しない

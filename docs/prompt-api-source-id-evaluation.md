2026-10-28、所有者承認の評価専用拡張。通常UIのentities-v1、日本語v1指示、1,600文字/重複200、既存NER、保存v1は変更しない。公開・デプロイ・マージは行わない。

## 評価条件とデータ

- 新データ版は `development-v2-balanced`。既存development/finalの値と過去の結果は変更しない。最終確認用データは使わない。
- 正例/否定例それぞれ記録番号あり・なしを同数にする。通常の組織名と、人名を含む組織名のストレス例を分離する。同じ本文の記録番号差分は対にして比較する。
- 初回は通常文・紛らわしい否定例・命令文・重複出現・境界・反復/非反復の少数集合で足切りする。設定・文書を固定して各3回。設定順は回ごとに回転し、順序を保存する。
- 各行にデータ版/文書SHA-256、設定SHA-256、実行ブラウザー版、UA、OS/端末、言語条件、上限、開始/終了時刻、準備/推論時間、前後の環境スナップショットIDを記録する。モデル版/GPUは実機のBroker状態で確認し、各行から記録IDを参照する。未測定の負荷は不明とする。
- 同一実機のモデル・ブラウザー試験は逐次実行し、他テストと重ねない。ブラウザー/モデル版が変われば同じ集計へ混ぜない。ウォームアップは本測定から分離する。
- 本文・生応答・例外本文は保存しない。明示取得した合成評価の件数・長さ・固定分類とハッシュだけをignore対象へ保存する。

## API失敗の比較

同じv1指示と入力について、構造制約あり/なし × 基準セッションのclone/区間ごとの新規セッションを比較する。制約なしでも計測・推論は同じ条件を使う。診断用の制約なし結果は、通常UIへ適用しない。

ストリーム完了、JSON/構造検証完了、内容警告、空白上限、60秒期限、文脈上限、API拒否を分ける。APIが完了しても構造違反を成功0件にしない。安全・言語拒否を迂回せず、UnknownErrorの内部原因を推測で確定しない。無制限再試行、タイムアウト延長、断片JSONの補修は行わない。

## entities-source-id-v2（評価専用）

入力は `sources: [{id, text}]`。id=0は区間全体、以降は区間内の連続した文・行の引用。空白・改行・UTF-16開始位置を保持し、最大64参照。後半や文/行をまたぐ対象はid=0を参照できる。番号自体は信頼できる命令やPIIの正解ではない。

出力は次の厳密なJSONとする。

```json
{"entities":[{"text":"合成の対象文字列","category":"PERSON","sourceId":1}]}
```

- 許可カテゴリはPERSON/ADDRESS/ORGANIZATION。各項目はtext/category/sourceIdの3キーだけ。sourceIdは入力表内の整数。対象なしは空配列。
- textは指定された参照内の連続完全一致でなければ棄却する。他の参照に同じ文字列が存在するだけでは受理しない。欠損キー・未知キー・不正ID・型/上限違反はジョブ全体を失敗にする。
- 引用はモデルに書き直させず、モデルが指定した参照の原文を使う。位置は指定参照内の一致だけからUTF-16で戻す。同一引用が別の参照にある場合、その別参照の位置を証拠として自動追加しない。
- sourceId=0の区間全体も有効な根拠。精度を保証する制約ではなく、生成量削減の仮説である。登録後の同一文字列一括マスクは既存規則を維持し、証拠位置とは別に最終置換範囲を評価する。
- 応答65,536文字、128項目、全体1,024候補、証拠50,000位置、構文空白連続1,024文字、60秒/300秒を維持する。sourceId、参照表、引用、位置をOPFSへ追加しない。

既存DET-02/03の生成evidence形式の代替を評価専用に認める。通常UIの契約・保存スキーマを移行する承認ではない。必要な受入条件は以下。

| 観点 | 正常/異常/境界/状態遷移 |
| --- | --- |
| データ・機能 | 正しい参照、違う参照、存在しないID、引用内の複数一致、同一引用の別ID、文をまたぐ対象、Unicode/JSON特殊文字、上限境界 |
| 非機能 | clone/新規の独立状態、遅延create/cloneの解放、中止・後半失敗で全破棄、計測と推論の制約一致 |
| 評価・プライバシー | 失敗も漏れへ計上、モデル完了と構造完了の分離、順序/ハッシュ/環境記録、エラー本文・生応答の非保存 |
| UI | 評価専用に限定し、通常の選択適用・保存・復元・非対応時の動作を対象回帰 |

## 継続の判定

2026-10-28の最終比較結果：参照重複削減・分割の78件で下記の進行条件を満たす案はなく、今回は採用見送り。既存NERとの組合せへは進めない。[実測・判定・検証境界](prompt-api-poc-report.md)を参照。以下の計画は判断を再現するために保持する。

### 最終の少数条件：参照重複削減・分割・条件付きNER比較

2026-10-28の所有者指示に基づき、今回は以下の3条件までを試す。旧sourceId指示、clone、スキーマ自動入力あり、再利用なし、構文空白/時間/件数上限、samplingを固定し、否定例向け指示2案は使わない。

| 条件ID | 参照 | 窓/重複 |
| --- | --- | --- |
| reference-control | 区間全体＋文/行（従来） | 1,600/200 |
| reference-whole | 区間全体ID0だけ | 1,600/200 |
| reference-whole-512 | 区間全体ID0だけ | 512/128 |

`whole-only`は原文全体をID0のtextに1回だけ渡し、文・行の重複とID選択を省く。出力の3キーは維持し、sourceIdのenumと検証器の許可IDをともに0だけにする。提供していないID1以降は全体失敗とする。指示の「参照0は区間全体」を保持し、文/行をまたぐ対象も失わない。新しい保存形式や通常UIの設定ではなく、評価専用の入力/制約条件である。全体参照内の同一文字列の全位置が証拠になる点は、従来ID0を使った場合と同じであり、位置精度の悪化も測る。

`referenceScreeningPlan()`は短文10文書（これまでと同じ正例6/否定例4）各3回でcontrol/wholeを計60件比較する。全短文は512文字未満でwhole-512も同じNative入力/制約になるため重ねて測定しない。反復する旧開発用1,000文字と非反復development-v2の1,000文字では3条件各3回、計18件。合計78件、各段階のウォームアップは別枠。既存データ・正解と独立最終データは変更しない。回ごとに条件順を回転し、同じ端末で逐次実行する。

短文には従来も参照がID0だけの文書がある。`referenceInputChanged()`で入力JSONとスキーマが変わる集合/同じ集合を分け、後者の出力の揺れだけを重複削減の効果としない。

NERとの組合せへ進む探索用の足切りは、測定前に`referenceScreeningGate()`で固定する。

- 78件に欠損・重複がない。短文wholeが30/30完了する。
- 未マスク、誤マスク、文字列/位置FP・FNが、総量・各文書3回合計・最悪回合計のいずれでも短文対照より悪化しない。
- 誤マスクが25%以上かつ2区間以上減る、または未マスクが2出現以上減る。さらに、入力/制約が変わった集合でも未マスクか誤マスクが減る。少数の揺れや速度だけでは進めない。
- 対象のwholeまたはwhole-512が長文6/6完了し、同じ各指標で長文対照への退行がない。各長文各回に完全一致の正解文字列TPが1以上あり、空抽出や短い不正抽出で速くなった結果を通さない。

これは統計的な非劣性の証明ではなく、少数比較を次段階へ進める保守的な条件である。通過があれば最も漏れ・誤マスクが少ない1条件を固定し、既存Regex＋NERのAと追加候補を選択適用したBを同じ開発用集合で比較する。NERの準備・推論成功を確認し、失敗を成功として扱わない。新しいモデル版への変更や独立最終データでの調整はしない。Bで漏れが減らず、誤マスク/確認対象が増えるだけなら採用しない。人の確認時間を未測定なら、その削減は実証済みとしない。

足切りを通る条件がなければNERとの組合せは実行せず、今回のPrompt API採用を見送る。既存の未公開PoC実装・証跡は維持し、所有者の別指示なしに本体を撤去したり公開したりしない。正常/異常/境界/状態遷移の単体で単一参照の厳密性、UTF-16/改行/重複位置、後半失敗の全破棄、足切りの欠損・退行・見せかけの改善を検証する。通常UIへ変更しないためE2Eは評価専用経路を選び、全件・大容量NER取得は既定にしない。

### 優先度0〜1の後続比較（誤分類・否定例・API最小再現候補）

通常UI・保存形式・参照表・検証規則は維持する。`negativeInstructionPlan()`は既存と同じ調整用10文書（正例6/否定例4、記録番号あり/なしの対）を各3回、旧sourceId指示と否定例向け追加指示だけを切り替えて計60件比較する。追加指示は固有名と一般語/項目名/番号の区別、対象なしの空配列、架空らしい固有名も省略しないことを述べる。例文は測定文と異なる固定合成例で、独立最終データは使わない。入力・スキーマ・clone・1,600/200・スキーマ自動入力・上限を固定し、回ごとに比較順を回転する。これは指示の因果比較であり、過去のv1結果を同時期の対照とは扱わない。指示の改善が成立した場合だけ、v1との追加比較や長文へ進める。

評価行には`errors.version=error-counts-v1`を追加する。登録文字列・抽出位置・最終置換区間それぞれについて、完全一致→同位置のカテゴリ違い→同カテゴリの境界違い→境界/カテゴリ複合→正解と非交差、の優先順で排他的に分類する。登録文字列は同じ正解文字列がある場合を先に判定する。正解側の未抽出もカテゴリ/境界/複合/非交差に分ける。同じ正解文字列の登録があっても対応する位置証拠がない件数は別記し、その原因を参照選択だけと断定しない。最終誤マスク区間数、誤マスクを起こしたエントリ数、一エントリあたり最大誤マスク区間数も数える。これらは合成正解との比較であり、実ユーザーの正解や運用時の自動除外規則には使わない。

位置・原文・候補・生応答・例外本文は行に追加しない。元の証跡から詳細分類を復元できないため、今回から取得した分類と過去の集計を分ける。失敗ジョブの部分結果は採用せず、全正解を未抽出として計上する。区間ごとのNative呼出番号・入力文字数・経過時間・Native完了だけを追加し、API拒否と構造検証失敗・期限切れを区別する。

`--phase minimize`は過去の失敗入力と設定（1,000文字、512/128、引用enum、再利用あり、clone、自動スキーマ入力なし）を基準に、元文の連続部分である末尾区間232文字・対象本文51文字・直前の一般文181文字を各3回、計12件測る。各回で順序を回転する。文を削ると入力と引用enumも変わるため、削除の効果を制約と無関係な内容の効果とは断定しない。

基準の再現を確認した場合、`--phase minimize-sentences`で接頭部半減＋本文、本文の第1文、第2文を各3回、計9件まで追加する。再現がなければ最小と認定せず、環境変動/フレークとして報告する。最短の失敗候補は「試した連続削除集合内」での結果であり、文字単位の大域最小や内部原因の証明ではない。UnknownErrorと同じでない失敗を最小再現の成功に数えない。安全・言語拒否の迂回、制約緩和による継続、期限延長、断片JSONの補修は行わない。

この21件で232文字のUnknownErrorは再現し、142文字は完了したため、境界と制約の追加比較を別manifestで固定する。`--phase minimize-boundary`は232文字の引用enumあり/なし、および元文から45文字を除いた187文字の引用enumありを各3回、計9件。232文字の2条件では制約だけを変え、通常v1スキーマでも厳密検証と全破棄を維持する。実ユーザー処理で拒否後に制約を外して継続する仕組みではない。187文字の結果から長さに単調な閾値があるとは推定しない。前2段階からソース指紋は変わるが、旧条件・指示・データのハッシュで比較対象を識別する。追加計画は否定例向け指示の60件を測る前に固定する。

最初の否定例向け指示で誤マスク減少と未抽出増加の交換が見られたため、追加は短い指示1案に限定する。`--phase negative-brief`は、カテゴリの定義や例文を増やさず「文脈上の名称のみ」「一般語・項目名・番号は対象外」「対象なしは空配列」を足す。同じ10文書各3回で旧sourceId指示を再度同時期の対照にし、計60件。最初の指示案や前回のv1結果を同時期の対照へ置き換えない。固定後に測定し、成立しなければ長文・全100文書への拡大は止める。

この段階から、sourceId検証の`text_missing`を「区間の別参照には対象があるwrongReference」「区間全体にないtextAbsent」に分け、`diagnostics.referenceErrors`へ件数のみ加える。受理/棄却規則と出力スキーマは変わらない。不正ID/型などの構造違反は従来どおり全体失敗とし、この件数へ混ぜない。前の段階にはこの内訳がないため、欠損をゼロとして合算しない。選択参照は正しいが意味分類が誤っている候補は、この参照誤りとは別に誤分類へ数える。

検証観点は、機能（排他的分類・同一文字列一括マスク・全破棄）、非機能（非同期中止・資源解放・Native呼出と再利用の区別）、データ（正例/否定例・カテゴリ/境界・反復・重複証拠・UTF-16位置・切り出し後の正解）、UI（通常設定と明示選択/保存の維持）。正常/異常/境界/状態遷移を単体で確認し、実モデルは逐次実行する。E2Eは評価専用変更に応じて選定し、全件や大容量NER取得は既定にしない。

少数の固定文書を各3回測定し、最悪回の漏れ/誤マスク、完了率、警告、生成文字数、準備/推論時間を比較する。失敗の早期停止は精度改善と数えない。基準より漏れを増やして誤マスクだけ減らす案は採用しない。通常条件で失敗する案は正式評価へ拡大しない。成立した案だけ調整用100文書へ進め、設定固定後に別の最終確認100文書各3回と確認負担を評価する。
